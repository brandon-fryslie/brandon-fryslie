# Stats Card Archive

Historical record of every "Live GitHub Stats" card that has appeared on the profile README. Written by `.github/scripts/sync-stats-archive.py`, which the `stats` job in `.github/workflows/daily-highlights.yml` runs each morning; not hand-edited.

## File layout

```
stats-archive/
  YYYY/
    MM/
      YYYY-MM-DD-HHMMSS.svg    ← the card, copied verbatim out of git history
      YYYY-MM-DD-HHMMSS.json   ← that day's headline numbers, for the gallery
```

- The stamp is the **author** date, in UTC, of the commit that introduced the card. Author date rather than committer date on purpose: the job's push loop rebases when it races the `doodle` and `narrative` jobs, and rebasing rewrites committer dates. Stamping from the committer date would let an already-archived card reappear under a second name after any contended push.
- Year and zero-padded month directories keep any single directory browseable in the GitHub UI and `ls`.
- Multiple entries on the same date are normal — every commit that changed the card gets its own file, so a day with two runs holds two cards.
- The `.json` sidecar is **not** a copy of `assets/daily-stats.json`. It holds only what the gallery renders — the day's metrics, plus the SHA of the commit the card came from. The full data seam already exists in git history at that SHA, and a second copy of it could only ever disagree with the first.

## How entries get added

The archive is **derived from git history**, not accumulated by copying files aside.

Every version of `assets/daily-stats.svg` that has ever been committed is a card that was live on the profile, so the commit log is already the authoritative list of which cards existed. Each run, the sync script walks that log, writes any card missing from the tree, and regenerates [`STATS.md`](../STATS.md) from the tree.

Three properties follow from that, and they are the reason for the design:

- **Backfilling and daily operation are the same operation.** There is no `--backfill` flag because there is nothing for one to select. The first run recovered six months of cards; every run since adds one.
- **It self-heals.** A run that was skipped, failed midway, or lost to a force-push is repaired by the next run, because the script compares history to disk rather than tracking what it has already done.
- **The gallery cannot drift from the tree.** `STATS.md` is regenerated by scanning the archive directory, so a card that is not on disk is not in the gallery and there is no third place to check. (The doodle archive works the other way round — the job copies the live SVG aside and *prepends* a gallery entry — which is why its gallery and its tree have to be kept in agreement by hand.)

Because history only contains what has been committed, the card authored on any given morning is archived by the *next* run. The live card is always the one on the README; the archive begins at yesterday.

## Where the captions come from

Each entry's caption carries that day's headline numbers so the gallery can be skimmed without opening 150 SVGs. Two eras produced the cards, and the sync script resolves both to one shape at ingest, so nothing downstream knows the difference:

- **August 2026 onward** — the card is authored fresh each day by a Claude invocation over `assets/daily-stats.json`. That seam is committed alongside the card, so the numbers are read straight from it.
- **Through July 2026** — the card came from the deterministic generator, which rendered every metric as a fixed trio of font sizes (value, label, period). Those are read back out of the card's own text.

The legacy reading is structural, not a guess: the count of values must equal the count of labels, or the card gets **no** caption at all. A caption assembled from mismatched labels and values would state numbers this profile never showed, which is worse than a card with no caption.

## What this archive is not

- **Not a workspace.** Nothing is edited in place. The sync script refuses to overwrite an existing card and fails loudly instead — an archived card differing from what history says it was means the file was hand-edited or history was rewritten, and either needs a deliberate decision, not a silent repair.
- **Not a second source of truth.** Git history is the source; this tree and `STATS.md` are both derived from it. If they disagree, delete and re-sync — never patch the tree to match the page.
